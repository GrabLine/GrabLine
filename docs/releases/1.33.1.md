# GrabLine 1.33.1

A fix release for pairing a phone (or another PC) with GrabLine.

## Pairing works on PCs with virtual network adapters

- The pairing QR code and the address shown under it now start with the address
  of the network your router is on (the adapter Windows sends internet traffic
  through). Before, a PC with Hyper-V, WSL, VirtualBox, Docker or a VPN could
  list one of those virtual adapters first, and the phone spent the code's two
  minutes trying addresses it can never reach.
- Virtual adapters are listed last, and the QR code lists at most four
  addresses, so it is smaller and easier to scan off the screen.
- Nothing else about listening changed: GrabLine still listens only on private
  and link-local addresses, only while pairing or with a paired device, and never
  opens a port in the router.

## The "Allow this device?" prompt

- **Allow** is now the highlighted button. It used to be **Deny**, which was easy
  to press by mistake. Escape and closing the prompt still deny.
- When a phone asks to pair, GrabLine comes to the front (also from the tray)
  and flashes in the taskbar, so the prompt is not hidden behind other windows
  while you look at your phone.

## Other changes

- The sidebar's **Devices** icon is now a monitor with a phone beside it,
  because Devices holds phones and other PCs alike.
- Closing GrabLine while Windows is shutting it down no longer writes a
  "Cannot operate on a closed database" error to the log.

## Verification

- Lint, format, `mypy app --platform linux` and the full Windows test suite.
- New tests for the address order (routed adapter first, virtual adapters last,
  at most four in the QR) and for recognising virtual adapters.
- Paired the owner's Redmi 12 (GrabLine for Android 0.1.5) with this release's
  code on a PC with Hyper-V, WSL, VirtualBox and Tailscale adapters, by typed
  code, with the address list starting at the LAN address.
